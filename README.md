# site-audit

A Claude Code plugin for presales website audits. Give it a shop's domain and it finds the issues that matter most to the owner, proves each one, and builds a short report for the sales call. It looks at performance, bugs, UX and UI, accessibility and technical SEO. You approve the report in chat, and it then goes to Google Drive as a Google Doc.

The report holds up to 15 findings, each with:
- the page;
- what a shopper sees;
- why it matters to the business;
- a current fix;
- proof: a screenshot, a measurement or the exact error.

Smaller items go to an "Also worth mentioning" list, and the report ends with the PageSpeed Insights data for the home, category and product pages. The audit runs as a guest: it never places an order, creates an account or submits a form.

> **Check the report before you send it.** The report is generated by AI and can contain mistakes: test artifacts, wrong numbers or advice that does not fit the shop. A person must review it and check every finding before it reaches a client.

## How it works

1. **Measure:** three scripts run in the background:
   - PageSpeed Insights, median of 3 runs per page, mobile and desktop;
   - HTTP checks: redirects, 404, robots.txt, page cache;
   - an SEO crawl of the sitemap.
2. **Walk:** three Walker agents (Sonnet) go through the shop one after another, in a desktop tab and a mobile tab:
   - home, header and footer;
   - search and category pages;
   - product, cart and checkout.
3. **Select:** the main session (Opus) picks the findings and drops test artifacts and normal platform behaviour.
4. **Prove:** the Prover agent (Sonnet) reproduces each finding and takes a proof screenshot.
5. **Filter:** the Reviewer agent (Opus, max effort) reads the built report and drops the findings a prospect's developer would dismiss in one sentence: test artifacts, advice the site already follows, normal platform behaviour, claims the proof does not support, generic advice. Small but valid ones move to the minor list. You see one line with what it dropped, so you can bring a finding back.
6. **Approve:** you get the `.docx` and a one-line-per-finding list. Changes are made locally until you approve, and only then is the report uploaded.

## Requirements

- **Claude Code** with a PRO plan. (One audit used about 20–25% of a 5-hour usage window)
- **Google Chrome** with the **Claude in Chrome** extension, create separate chrome profile for that without Chrome extension exclude **Claude in Chrome**.
- The **Google Drive** connector enabled in your Claude account, for the upload.
- A **PageSpeed Insights API key**, free (see Setup).

## Install

The repository is a plugin marketplace. In Claude Code:

```
/plugin marketplace add alexandrgasnuk/claude-site-audit
/plugin install site-audit@claude-site-audit
```

Restart Claude Code. The repository is private, so git on your machine needs access to it, through `gh auth login` or an SSH key.

To have Claude Code offer the plugin to everyone who opens a shared project, add this to the project's `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "claude-site-audit": { "source": { "source": "github", "repo": "alexandrgasnuk/claude-site-audit" } }
  },
  "enabledPlugins": { "site-audit@claude-site-audit": true }
}
```

## Setup

1. **PageSpeed Insights key:**
   1. Google Cloud console → APIs & Services → Library: enable the "PageSpeed Insights API".
   2. Credentials → Create credentials → API key.
2. **Config file:** put the key and the Drive folder for the reports in `~/.config/site-audit/config.json`:

   ```json
   {
     "psi_api_key": "AIza...",
     "drive_folder_id": "1AbC..."
   }
   ```

   - `drive_folder_id` is the last part of the folder's URL in Google Drive. Without it, reports go to the root of My Drive.
   - The key can also come from the `PSI_API_KEY` environment variable.
   - Never commit this file.
3. **Effort:** check that `CLAUDE_CODE_EFFORT_LEVEL` is not set, in your shell or in the `env` block of `~/.claude/settings.json`. It overrides the effort the skill and its agents set for themselves, and it makes every agent run at that level, which multiplies the cost.

## Customize

Adapt the audit with your own rules, such as findings you never want, advice your team gives or avoids, extra checks, or report preferences. They live outside the plugin, so updates never overwrite them:

| File | Who it is for |
|---|---|
| `~/.config/site-audit/custom.md` | Your own rules, in every audit you run |
| `site-audit.custom.md` in the working folder | Rules shared by everyone who audits from that folder |

To start, copy the template from the plugin's `skills/site-audit/templates/custom.md` and write plain sentences under its headings. The rules take priority over the skill's own files, and the working-folder file wins over yours. Only the safety rules cannot be changed: the audit never places an order, enters payment details or a password, or submits a form.

A rule that would help everyone belongs in the skill itself; see "Improve the audit".

## Run an audit

1. Close every incognito window, then open a new one. The audit needs a clean session: an empty cart and the first-visit popups.
2. Open Claude Code in a working folder of your own, not in this repository. Reports are written to `./audits/<domain>/` there.
3. Ask for an audit, for example:

   ```
   /site-audit:site-audit example.com
   ```

   or simply "audit example.com for sales". Add pages or areas to focus on if you like.
4. Answer its one setup question:
   - **Mobile tab:** turn on DevTools device emulation in the tab it names (F12 → device toolbar → a phone such as iPhone 12 Pro).
   - **Which store:** if the shop has several country stores, say which one to audit.
5. Wait. While the agents and scripts work, the main session waits and reports one line per step.
6. Review the report. You get the path to the `.docx` and the findings list. Ask for changes in chat; they are made in `findings.json` and the report is rebuilt.
7. Approve it. The report goes to Google Drive, and you get the link and a status line for the tracking sheet.

### Rules the audit follows

- **Guest only.** In checkout it fills in test data (country, postcode, the name "Test Audit", `audit-test@example.com`) so that shipping and payment methods appear.
- **Never orders.** It never presses "Place order" or "Pay", never enters card details or a password, and never ticks terms checkboxes.
- **Proof for every finding.** A finding without proof stays out, and so does generic, outdated or doubtful advice.

## Improve the audit

The skill learns from the findings you reject. Most improvements are a line or two in a reference file:

| File | What goes there |
|---|---|
| `references/judging.md` | **"Not findings":** normal platform behaviour that must not be reported. Also performance causes, and "Recommendations to avoid" |
| `references/sources.md` | Checked sources for statistics and rules, each with its quote and date |
| `references/checklist.md` | What the Walkers look at, and the browser snippets they run |
| `SKILL.md` | The workflow |
| `agents/*.md` | The Walker, the Prover and the Reviewer |

To contribute:
1. Make a branch and edit.
2. Run `claude plugin validate plugins/site-audit`.
3. Raise `version` in both `plugins/site-audit/.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`.
4. Open a pull request.

Test changes on a real audit, not by re-running finished ones.

```

  .claude-plugin/plugin.json         the plugin
  agents/                            site-audit-walker, -prover, -reviewer
  skills/site-audit/

```

## Troubleshooting

- **The browser tools don't work in incognito:** the extension is not allowed in incognito windows. See Requirements.
- **"Agent type not found":** the skill falls back to general-purpose agents that read the same definitions, so the audit still runs. Restart Claude Code after installing or updating to bring back the proper agents.
- **The audit costs far more than usual:** check `CLAUDE_CODE_EFFORT_LEVEL` (Setup, step 3).
- **No PageSpeed data:** check the key and that the PageSpeed Insights API is enabled for its project.
